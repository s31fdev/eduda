## Повторение на рабочей базе

1. Сверить свежий план с манифестом. Проверить совпадение школ, учеников, кошельков, записей и сумм. При расхождении разобрать затронутые пары по рабочим данным.
2. Для совпавшего набора 88 пар применить скрипт с проверенным манифестом.
3. Для десяти отдельных правок в транзакции проверить, что обе записи активны, относятся к одному ученику, кошельку и организации, не привязаны к счёту, а сумма и дата денежной записи совпадают с таблицей. Проверить цену, остаток, размер и журнал пакета. Списанная выручка до переноса составляла 12 067 ₽ для №3067 и 6 264 ₽ для №3112. У восьми пакетов с изменением цены списаний не было. Если с момента локального прогона произошли списания, пересмотреть правку по текущим данным.
4. Перенести полную сумму и исходное значение `createdAt` из денежной записи в пакет, установить сумму денежной записи в 0 ₽. У восьми неначатых пакетов установить новую цену урока из таблицы. У №3069 сумма 1 989 ₽ делится на два урока по 994 ₽ с округлением вниз, 1 ₽ остаётся в авансе после обоих списаний. Проверить, что итог по паре и исходная дата поступления сохранились.
5. Запустить `apps/platform/scripts/check-ledger.ts` и сверить остатки, выручку и поступления по датам. Сверить отображение в карточке кошелька и кабинете родителя после доставки кода с фильтром пустых записей.

## Нулевые счета для пакетов перехода

В локальной `alg` созданы 147 отдельных оплаченных счетов на 0 ₽. Список связей находится в `2026-11-10-legacy-zero-payments-local.json`. ID новых счетов на проде будут другими.

После переноса исторических оплат запустить из `apps/platform` команду `pnpm exec tsx scripts/create-legacy-zero-payments.ts` и сверить список кандидатов с рабочими данными. Затем выполнить ту же команду с `--apply`. Повторный просмотр должен вернуть пустой список. Скрипт выбирает активные пакеты «Остаток на начало учёта пакетов» в активных кошельках с уроками, нулевой суммой и без счёта. Остаток и журнал проверить через `scripts/check-ledger.ts`.

Скрытые денежные записи «Оплачено до перехода» без счёта и с 0/0 остаются в базе для сверки. Код исключает их из списков кошельков, кабинета родителя и отчёта «Авансы».
